# Build 187 — Canonical Security Incident Cases & Independent Closure Evidence

**Release scope:** Staff-only canonical security/safety incident intake, investigation, escalation, optional validated link to a Build 063 access/device signal, protected guest/witness context, confidential evidence attachments and independently reviewed closure or return. **Billing / Omnichannel remain HELD / DISCONNECTED.** No outbound messaging, provider activation, gate commands, device writes, or emergency-contact automation is introduced.

## What is authoritative

- `/workspaces/security/incidents` is a campground-scoped, authenticated staff board. Only `security.incident.manage` and/or `security.incident.review` grants access to a case; the independent reviewer permission is distinct from intake/investigation. The `security` template gets intake/investigation and restricted evidence permission. `campground_manager` gets independent review and restricted evidence permission; `owner_admin` has both. Custom roles can be tailored using the existing permission catalogue.
- Cases, their append-only events, protected person context, confidential attachments and immutable independent review receipts live in private PostgreSQL tables with forced RLS. `icamp_app` has **read-only**, campground-authorized access, while direct `anon` / `authenticated` access and any direct `icamp_app` writes are disallowed. Server mutations independently re-check the actor's current assignment and permission and serialize each case with a row lock and optimistic version check.
- A source signal is only an optional, validated **link** to an actual denied access event, device-fault event or failed/rejected/timed-out/unsupported override outcome in the same campground. A cleared or disappeared signal is never a case closure. No access token, keypad credential or device secret is copied to incident records.
- Only `security.incident.sensitive.read` can see or update witness/guest context or see attachment metadata. The generic confidential media endpoint also requires this incident permission when an asset belongs to an incident. Uploads are limited to validated images/PDFs through the existing confidential bucket; metadata captures SHA-256, and the media lifecycle is frozen after it is linked. The signed URL is available only after case-specific and confidential-media authorization; responses are private and no-store.
- Cases require an investigation update and at least one still-active, validated confidential attachment to request closure. A separate `security.incident.review` actor must not be the reporter, current assignee, closure requester, investigator, assigner, escalator or evidence author. The independent review receipt records a 20–1500 character rationale and one of **returned** or **approved**. Database triggers require an approved receipt before transition to `closed` and prevent mutation/deletion of reviews, events, attachments, cases or attached media. Returning a case forces another closure round; reopening a closed incident records a new event and leaves its prior receipt intact.
- Sensitive context changes while closure is pending return the case to investigation for another request. General audit events contain safe metadata without witness/guest narratives, and signed storage URLs are never logged to case history.

## Acceptance gates

1. `npm test` covers severity/category validation, signal pairing, self-review denial, missing or invalid closure evidence, private route rules and the held integrations boundary.
2. PostgreSQL 17 migration and `database/verify/0197_build187_canonical_security_incidents.sql` validate forced RLS, principal grants, retention guards, review gates and append-only history.
3. `npm run build187:verify` runs a **rollback-only** synthetic lifecycle: missing-evidence closure denial, investigation and attachment, refusal to delete evidence, self-review denial, approval only by a separate staff reviewer, immutable review/case retention, campground RLS isolation and front-desk denial. Synthetic test data never persist.
4. Existing repository CI (format, ESLint, TypeScript, node tests, browser end-to-end, parity, PostgreSQL 17, production build, dependency audit), CodeQL and secret scans must pass before merge. Remote Git refs, hosted migration, Vercel deployment SHA, live `/api/version`, `/api/health/ready` and runtime errors determine production GREEN, not this document alone.

## Limits and next build

No case is generated from a signal automatically. Confidential attachment upload requires working private Supabase Storage configuration; if unavailable, the UI fails closed without recording an unattached case artifact. The new restricted interface is Web/PWA and staff-assisted only—emergency dispatch, voice, SMS and physical gate actions stay disabled. **Build 188:** Visitor/Vehicle/Access Credential Lifecycle & Safe Reconciliation, with physical integration HELD.
