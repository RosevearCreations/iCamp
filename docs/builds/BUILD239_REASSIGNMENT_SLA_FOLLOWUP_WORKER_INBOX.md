# iCamp Build 239 — Fulfillment Reassignment, SLA Exception Follow-Up & Worker Mobile Inbox

## Scope

- iCamp is the full multi-campground SaaS product. Camp Rosevear is one
  customer/sample campground with independent reservations, staff, guests and
  decisions. Master Shell and Comms Hub remain outside each tenant's operations.
- Build 239 extends existing assignment and dispatch sources. It does not
  create a second job queue, send messages, change charges, edit reservations,
  control gates or automatically escalate to the Rosevear Master Shell.

## Implementation

1. Migration `0224_build239_reassignment_sla_followups.sql` captures assignment
   and reassignment changes in an immutable, source-triggered ledger with the
   actual previous/new worker, assignment version, author, UTC timestamp and
   required reason when changing or removing an existing worker. No earlier
   history is invented. The prior Build 238 dispatch becomes superseded by a
   version change; a supervisor must explicitly dispatch again.
2. A separate supervisor-only append-only SLA review table requires actual
   observed late/overdue acknowledgements, worker support requests, or
   completion exceptions. The database freezes the source signal(s) when the
   supervisor records investigation, awaiting-worker, resolution or reopening.
   Latest-review identity and unique chaining block duplicate/stale decisions.
3. A mobile-first worker inbox displays only handoffs addressed to the signed-
   in worker, 20 per page, prioritizing current unanswered receipts by due
   time and exposing worker-only receipt/support forms.
   Superseded handoffs remain clearly labeled historical evidence.
4. All reads/writes enforce campground permission, scoped role and forced RLS.
   A worker cannot read other workers' dispatches or supervisor-only review
   notes. Audit events are emitted for supervisor follow-up decisions; source
   assignment transitions are generated by a database trigger.

## Acceptance and deploy evidence

- `node --test tests/build239-reassignment-followup-inbox.test.mjs`
- `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm test`,
  `npm run build`.
- Migration 0224 and `database/verify/0224_build239_reassignment_sla_followups.sql`.
- Protected `dev` / `main` GitHub PRs, post-merge checks, exact Vercel main
  production revision READY.

**Operational HOLD:** CI database migration success does not prove adoption in
the live hosted Camp Rosevear database. Before using with live staff, the
authorized owner must verify migration 0224, employee/role isolation, an
actual supervisor reassignment and a worker acknowledgement on a real device.
No synthetic test or ChatGPT acknowledgement can provide that owner proof.
